# Задание для агента: довести AZIZ WEBSITE до продакшена

Ты работаешь в уже готовом проекте **AZIZ WEBSITE** (открытая папка). Это SaaS-конструктор интернет-магазинов в Telegram.
Сначала прочитай `README.md` — там архитектура, схема БД и шаги деплоя. Не переписывай архитектуру и не меняй стек.

## Что уже сделано и проверено
- Next.js 14 + TypeScript + Tailwind: лендинг `/`, 10 шаблонов (`shared/templates.json`), витрина `/shop/<slug>`, демо `/demo/<шаблон>`, кабинет `/panel`, визуальный редактор `/panel/shop/<id>/editor`, админка `/admin`.
- FastAPI (`backend/`, точка входа `api/index.py`), SQLAlchemy 2 + asyncpg, aiogram 3 бот (`backend/bot/`), один проект Vercel (`vercel.json`).
- `python scripts/smoke_test.py` — 85 проверок API проходят (на SQLite). `npx next build` проходит. Основные сценарии проверены в браузере.

## Что НЕ проверено — это твоя задача
1. **Локальный запуск.** `npm install`, создать `.venv`, `pip install -r requirements-dev.txt`, скопировать `.env.example` в `.env` (для локального режима `DEV_MODE=true`, любой `JWT_SECRET`), `npm run dev`. Запустить `python scripts/smoke_test.py` — должно быть «OK: 85 checks passed».
2. **PostgreSQL.** Попроси у пользователя строку подключения (Neon / Supabase / Vercel Postgres) и пропиши её в `.env` как `DATABASE_URL`. Перезапусти API на чистой базе и снова прогони `scripts/smoke_test.py` — все проверки должны пройти уже на PostgreSQL. Исправь всё, что упадёт.
3. **Telegram-бот.** Попроси пользователя создать бота у @BotFather и дать `BOT_TOKEN`, а также его Telegram ID для `ADMIN_TELEGRAM_IDS`. Подними HTTPS-туннель (например, `cloudflared tunnel --url http://localhost:3000`), пропиши его адрес в `WEBAPP_URL`, запусти `npm run bot`. Вместе с пользователем пройди в Telegram: `/start` → «Создать сайт» → выбор шаблона → «Смотреть демо» → «Выбрать этот шаблон» → название → ссылка → Telegram → «Сайт успешно создан!» → «Редактировать» (открывается Web App, вход по initData) → «Продлить аренду» (счёт в Stars) → `/login` (вход с компьютера). Проверь кнопку «Заказать в Telegram» на витрине и что продавцу приходит уведомление.
4. **Деплой на Vercel.** `git init`, первый коммит (`.env` не коммитить — он в `.gitignore`), попроси пользователя создать репозиторий на GitHub и запушь. Импорт в Vercel (Framework: Next.js). Сгенерируй секреты: `JWT_SECRET` и `WEBHOOK_SECRET` (`python -c "import secrets;print(secrets.token_urlsafe(48))"`), `ENCRYPTION_KEY` (`python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"`), `CRON_SECRET`. Заполни все переменные из `.env.example` в настройках проекта Vercel, `DEV_MODE` не включать. После деплоя проверь `https://<проект>.vercel.app/api/health`, войди в `/admin` через `/login` из бота и нажми «Настроить бота» (регистрирует webhook и кнопку меню). Убедись, что cron `/api/cron/daily` есть в настройках Vercel.
5. **Финальная проверка на проде.** Создай тестовый магазин через бота, открой его по ссылке `/shop/<slug>` на телефоне, отредактируй дизайн и товары в редакторе, опубликуй, проверь заказ в Telegram и админку (продление, блокировка, подтверждение оплаты).

## Улучшения после запуска (по согласованию с пользователем)

- Добавить миграции Alembic вместо автоматического `create_all`.
- Ограничить частоту запросов к `/api/public/shops/<slug>/event`.

## Правила
- Токены, пароли и строки подключения проси у пользователя; никогда не вписывай их в код и не коммить `.env`.
- Токены ботов продавцов должны храниться только зашифрованными на сервере и не попадать во frontend — не ломай это.
- Интерфейс остаётся на русском (витрина — русский/узбекский), стиль — чёрный фон и золотые акценты.
- После каждого шага кратко сообщай пользователю результат; если что-то не работает — покажи ошибку и исправь.
